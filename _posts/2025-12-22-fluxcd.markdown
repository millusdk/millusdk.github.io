Having setup a kubernetes cluster in my Proxmox homelab, I want an easy way to deploy my test applications to the cluster, without needing to setup loads of pipelines.

To do this I have chosen to use the GitOps tool [Flux](https://fluxcd.io/). Flux is a continous deployment tool for GitOps workflows, where it monitors your git repositories and reconciles the setup in the Kubernetes Cluster with the definitions in your git repository.

## Setup
Flux is actually really easy to setup. You need to install the their CLI tool on the same computer as you have kubectl installed, and once that is done, you simply run the bootstrap command pointing at an empty repository, I have pointed it at my own Gitlab server, meaning that the command looks as follows:

{% highlight bash %}
flux bootstrap gitlab  --token-auth --hostname=<gitlab hostname> --owner=kubernetes --repository=flux --branch=main --path=clusters/home
{% endhighlight %}

In the command you can see that the repository is placed in the kubernetes group and called flux. adding the parameter `--apth=cluster/home` allows me to later setup and run flux on multiple kubernetes clusters, with the current one being called `home`.

Once th command has been run, you will be asked for a PAT for the gitlab instance. I have created a user on my Gitlab instance falled "Flux", which is able to connect to Gitlab and read and commit data from the to repositories.

## Example repo
I have created a sample repository as an example to see that flux is working correctly.
The repository deploys the whoami webservice from Traefik.
The setup of the resources for the repository consists for four files:

deployment.yaml
{% highlight yaml %}
apiVersion: apps/v1
kind: Deployment
metadata:
  name: whoami
spec:
  replicas: 1
  selector:
    matchLabels:
      app: whoami
  template:
    metadata:
      labels:
        app: whoami
    spec:
      containers:
        - name: whoami
          image: traefik/whoami
          ports:
            - containerPort: 80
{% endhighlight %}

service.yaml
{% highlight yaml %}
apiVersion: v1
kind: Service
metadata:
  name: whoami
spec:
  ports:
    - port: 80
  selector:
    app: whoami
{% endhighlight %}

ingress-route.yaml
{% highlight yaml %}
apiVersion: traefik.io/v1alpha1
kind: IngressRoute
metadata:
  name: whoami
spec:
  entryPoints:
    - web
  routes:
    - match: Host(`<hostname for service>`)
      kind: Rule
      services:
        - name: whoami
          port: 80
{% endhighlight %}

kustomization.yaml
{% highlight yaml %}
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
- deployment.yaml
- ingress-route.yaml
- service.yaml
{% endhighlight %}

With the sample repository setup and ready, it is now time to configure flux to watch the sample repository.

First we need to add the sample repository as a source for Flux.
In the git repository from earlier containing the flux setup, run I run the following command:
{% highlight bash %}
flux create source git whoami --url=<url for the sample repo> --branch=main --interval=1m --export > ./clusters/home/whoami-source.yaml
{% endhighlight %}

After this, we setup the kustomization:

{% highlight bash %}
flux create kustomization whoami --target-namespace=whoami --source=whoami --path="./" --prune=true --wait=true --interval=30m --retry-interval=2m --health-check-timeout=3m --export > ./clusters/home/whoami-kustomization.yaml
{% endhighlight %}

Once the files have been created we commit them to the repository and push them to the remote that flux monitors.
After this, all we need to do is wait for flux to pickup the repository and deploy the application to the whoami namespace.
